# Automated Tests

Automated test suite using Node.js's native test runner (`node:test`, `node:assert`) with `tsx` for TypeScript execution.

Run all tests:
```bash
npm test
```

## Test Suites
- `storage.test.ts`: CRUD operations for projects, applicants, sessions, and users.
- `validation.test.ts`: Input validation, GitHub account age calculations, and XSS sanitization.
- `github_fake.test.ts`: Mock GitHub API behavior (OAuth token exchange, admin access checking, collaborator invitation calls).
- `auth.test.ts`: Session cookie cryptographic signing, verification, and tamper resistance.
- `crypto.test.ts`: AES-256-GCM encryption/decryption round-trip, re-encryption behaviour, tamper rejection, missing-secret failure, and legacy token compatibility.
- `credentials.test.ts`: Local and Cloud KMS credential vaults, AAD binding across user/platform/connection, key versioning, provider isolation, and fail-closed errors.
- `secrets.test.ts`: Environment and Secret Manager secret stores, name normalisation, caching, and no env fallback in gcp mode.
- `connections.test.ts`: Owner- and project-scoped connection storage, encrypted OAuth tokens, bot platform token rejection, verified bot channel connection, refresh-token retention, disconnect cleanup, and reconnect.
- `connections_api.test.ts`: Connection API authentication, validation, owner enforcement, token leakage checks, bot channel connection without a token, and disconnection.
- `bots.test.ts`: Discord permission bitfields and overwrite precedence, Discord/Telegram channel verification with fake fetch, unsupported channel types, safe error mapping, no token in errors or URLs, and every mock failure path.
- `publish.test.ts`: Owner-only publishing, approval and approval-hash gates, in-progress and duplicate refusal, manual retry after failure, Discord/Telegram independence, missing bot token fail-closed, and publication cleanup on project delete.
- `publish_api.test.ts`: Publish route authentication, 404/403/400/409/502 mapping, and no message text, bot token, or ciphertext in responses.
- `bluesky_adapter.test.ts`: AT Protocol session creation, verification, refresh and one-shot retry, concurrent single-flight refresh and reuse, rotated tokens attached to failed and ambiguous sends, grapheme/byte limits, rate-limit and revoked mappings, uncertain network sends, and the deterministic mock client. Every response comes from a fake `fetch`.
- `mastodon_adapter.test.ts`: Instance URL normalization and SSRF rejection (including IP literals), minimal-scope app registration, OAuth URL/code exchange, account verification, per-instance character limits (v2/v1/default), rate limits, server errors, uncertain sends, and the deterministic mock client.
- `mastodon_ssrf.test.ts`: Public/private/reserved IPv4 and IPv6 classification, IPv4-mapped addresses, mixed DNS answer sets, metadata endpoints, failed lookups, per-request rebinding revalidation, redirect refusal to loopback or private hosts, the production pinned transport refusing to open a socket for a non-public address, its TLS/hostname options, and a loopback socket proving the pinned lookup connects to the validated address under Node's family autodetection.
- `oauth_accounts.test.ts`: Bluesky app-password connections, encrypted token storage and retrieval, revoked-account disconnect, account-switch and reconnect approval invalidation, compare-and-set refresh persistence, Mastodon OAuth state hashing/expiry/denial/error paths, session binding, concurrent callback single-use, destination-change approval invalidation, callback redirects that ignore attacker-controlled host headers, publishing through the existing engine (limits, rate limits, duplicates, uncertain, revoked, post-refresh failures), independent platform failure, ownership isolation, API no-leakage checks, file-backed storage round-trips, and credential redaction in logs.

- `publication_state.test.ts`: UI/API publication state derivation, including the fail-safe rule that stale or unreadable `sending` rows are uncertain and never retryable, and that failed sends need a current approval before a manual retry.
- `rate_limit.test.ts`: IP-based sliding-window rate limiting, headers, and quota enforcement.

- `explore_api.test.ts`: Public listing discoverability (direct join and screening), referral/private exclusion, role and search filters, and My Applications visibility for private requests.

## Rules
- Automated tests must **never** make live network requests to real GitHub, Discord, Telegram, Slack, Bluesky, Mastodon, X, Reddit, LinkedIn, WhatsApp, OpenAI, Anthropic, Gemini, Brave Search, or GCP. Platform clients are tested with fake `fetch` or the mock transport; WhatsApp has no network path at all, and AI tests use the deterministic mock provider and fake search.
- Tests do not require real Bluesky accounts, app passwords, Mastodon instances, X or Reddit apps, LinkedIn apps, Slack apps or workspaces, WhatsApp accounts, AI provider keys, search keys, or OAuth credentials.
- All tests must pass before any change is completed.
