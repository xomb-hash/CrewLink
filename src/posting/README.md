# Posting (`src/posting`)

Drafting, connection, and publishing code for multi-platform posting. Discord and Telegram publish through Crewlink-owned bots; Slack publishes through a Crewlink Slack app installed in the owner's workspace; Bluesky, Mastodon, X, Reddit, and LinkedIn publish through creator-owned accounts; WhatsApp is manual-only (Crewlink prepares an official share link and the owner sends it by hand). Every other platform is still draft-only.

- `drafts.ts`: deterministic post copy per platform.
- `checks.ts`: validates character limits, grapheme clusters, missing join links, secret-looking strings, private repo links, and recent duplicates. X drafts are checked part by part with the official weighted count.
- `credentials.ts`: versioned credential vault for per-creator access and refresh tokens. The `local` provider uses AES-256-GCM with `ENCRYPTION_SECRET_V{n}` keys (`local:v{n}`); the `gcp` provider uses Cloud KMS and is selected by `CREDENTIAL_PROVIDER=gcp`. Every ciphertext is bound with AAD to `userId` + `platformId` + `connectionId`. There is no automatic fallback between providers, and decrypt failures throw.
- `secrets.ts`: application-level secrets (OAuth client secrets, shared bot tokens). The `env` provider reads `process.env`; the `gcp` provider reads Secret Manager with the `GOOGLE_SECRET_MANAGER_PREFIX` prefix and a short cache. A Secret Manager failure throws; it never falls back to env vars.
- `connections.ts`: owner- and project-scoped connection records. OAuth tokens are encrypted before storage, summaries never include token material, and a disconnected connection has its ciphertext wiped. `getConnectionToken`/`decryptConnectionTokens` only return tokens for an active connection owned by the caller. Bot platforms reject pasted tokens; `connectBotChannel` verifies the channel first and saves an active record with provider `none` and no ciphertext. `connectBlueskyAccount` signs in with an app password once and stores only the resulting encrypted JWTs. `beginMastodonAuthorization`/`completeMastodonAuthorization` register the instance OAuth app, store only the sha256 hash of a 10-minute state plus an encrypted pending client secret, and save the encrypted access token after the callback verifies the account. `beginXAuthorization`/`completeXAuthorization` use the same hashed, session-bound, single-use state and atomic claim, and keep the PKCE verifier and redirect URI only inside the vault-encrypted pending payload. `beginRedditAuthorization`/`completeRedditAuthorization` reuse that state pattern (32 random bytes, sha256 at rest, 10-minute expiry, session hash inside the encrypted pending payload) and store the encrypted access/refresh tokens after verifying `u/{name}`; they request only `identity read submit`. `beginLinkedInAuthorization`/`completeLinkedInAuthorization` request only `openid profile w_member_social`, use the same hashed/session-bound/single-use state and atomic claim, and have no PKCE because LinkedIn does not document it. The callback verifies `GET /v2/userinfo` and stores the encrypted access token plus the member id; LinkedIn issues no refresh token to ordinary apps, so an expired token disconnects the record and asks for a reconnect rather than faking a refresh. `beginSlackAuthorization`/`completeSlackAuthorization` use Slack OAuth v2 with only the bot scopes `chat:write channels:read groups:read` (no user scopes), exchange the code server-side, verify the bot with `auth.test`, and store only the encrypted bot token plus the workspace id/name, bot user id, granted scopes, and install metadata. `listSlackChannels`/`selectSlackChannel` use the bot token alone, so private channels appear only when the bot is already a member; a channel is activated only after verifying it is not archived and the bot can post (`not_in_channel`/`restricted_action` are refused), and Crewlink never auto-joins a channel. Changing the channel or workspace invalidates approved Slack drafts, reconnect reuses the same connection row, and disconnect calls `auth.revoke` and wipes the ciphertext. The pending handshake is bound to the signed-in session that started it and is consumed atomically before the code exchange, so replays, concurrent callbacks and a second session cannot redeem it. Refreshed tokens are persisted with a compare-and-set against the token ciphertext the caller loaded, so an older refresh never overwrites a newer session or restores tokens onto a disconnected record. Switching Bluesky accounts, Mastodon destinations, X accounts, Reddit accounts, LinkedIn accounts, or Slack workspaces invalidates approved drafts; revoked credentials disconnect the record. Pasted tokens are rejected for X, Bluesky, Mastodon, Reddit, LinkedIn, and Slack.
- `adapters/`: creator-owned account clients, isolated from the Discord/Telegram bot code.
  - `adapters/types.ts`: neutral session/account/post shapes and `AdapterError` codes (`auth_failed`, `token_expired`, `revoked`, `validation_error`, `rate_limited`, `instance_error`, `transport_error`, `uncertain`).
  - `adapters/http.ts`: shared JSON/form request helper, timeouts, retry hints from `retry-after`/`ratelimit-reset`/`x-ratelimit-reset`, and a `networkErrorCode` switch so ambiguous sends become `uncertain`. `x-ratelimit-reset` is seconds remaining (Reddit); `ratelimit-reset` is an epoch (Bluesky). Account-platform calls pass a DNS guard; redirects are never followed.
  - `adapters/ssrf.ts`: resolves every A/AAAA answer, rejects non-public addresses (loopback, private, carrier-grade NAT, link-local, multicast, documentation, reserved, IPv4-mapped private), then pins the socket to the validated address so a rebinding answer cannot redirect the connection. The pinned lookup supports both the single-address and Node 20+ family-autodetection (`all: true`) callback shapes, and TLS keeps SNI and certificate verification bound to the original instance hostname. Also enforces the response size cap and hard timeout. Redirects are never followed.
  - `adapters/bluesky.ts`: AT Protocol `createSession`/`getSession`/`refreshSession`/`createRecord`, 300-grapheme and 3000-byte checks, proactive and one-shot token refresh, and an `at://` URI result. Concurrent refreshes for one connection share a single rotation and reuse it briefly; rotated tokens are attached to failed or ambiguous sends so the caller can keep them. The app password is only used to create the session and is never stored.
  - `adapters/mastodon.ts`: public-HTTPS instance normalization (DNS names only; IP literals and local names are rejected), `read:accounts write:statuses` app registration, OAuth URL/code exchange, account verification, per-instance character limits (v2 with v1 fallback, cached 10 minutes), and status sends with `Idempotency-Key`. Every outbound call resolves and validates the instance address through `ssrf.ts`.
  - `adapters/index.ts`: returns live clients only when `PUBLISHING_TRANSPORT=live`; otherwise deterministic mocks. `setOAuthClientForTests` injects fake clients without network access.
- `bots/`: the Discord and Telegram clients plus the default mock transport.
  - `bots/types.ts`: shared client interface, verified channel shape, and safe `BotError` codes.
  - `bots/discord.ts`: Bot API v10 verification (guild membership, channel type, permission bitfields with overwrite precedence) and message sending with mentions disabled.
  - `bots/telegram.ts`: `getMe`/`getChat`/`getChatMember` verification (admin rights, `can_post_messages` in channels) and `sendMessage`. The token is in the URL path, so URLs are never logged or echoed.
  - `bots/mock.ts`: deterministic fake clients used unless `PUBLISHING_TRANSPORT=live`. Channel ids `mock-not-found`, `mock-not-member`, `mock-missing-permissions`, `mock-unsupported`, `mock-rate-limit`, and `mock-send-fails` exercise each failure path without a network call.
  - `bots/index.ts`: loads bot tokens from the secret store and fails closed when they are missing.
- `publish.ts`: publishes one approved draft to one bot or account platform. It requires the project owner, an approved draft whose text and sha256 hash still match, an active connection with a destination, and no existing publication. Records go `sending` → `published`/`failed`; duplicate and in-progress attempts are refused, and a failed attempt can be retried manually. Retrying uses `storage.claimFailedPublication`, a conditional update (`failed` + no external id → `sending`) so concurrent retries cannot both send. A `sending` row older than 15 minutes is reported as `uncertain` and is never resent; an ambiguous adapter result, or a send that succeeded but could not be recorded, also stays `sending` and returns `uncertain`. Adapter failures map to `auth_revoked` (which also disconnects the account), `rate_limited`, `invalid_post`, or `platform_error`. Refreshed Bluesky tokens are saved after a successful send, a definitive failure, and an uncertain send; a save failure only logs a warning so it cannot turn a live post into a failure. Mastodon sends pass the publication id as an idempotency key. Changing the connected channel, server, account, or instance calls `storage.invalidateDraftApprovals`, so approved drafts for that platform must be approved again. Every platform shares no sending state with the others. For X, automatic publishing additionally requires `confirmCost` and, when supplied, a `maxCostUsd` that covers the server-computed estimate; it reserves ledger budget before the first request and posts thread parts sequentially, chaining each reply to the previous id. A 401 is refreshed once and retried only for the part that was never created. Once any thread part has an external id, a later failure becomes a non-retryable `partial_thread`. `markPublishedManually` is the free X path: it never contacts X, never touches the ledger, requires the same owner/approval/hash checks, records `mode: 'manual'` with no connection or external ids, and returns `verified: false`. The `/publishing` UI labels it "Marked published manually" and never implies X confirmation. Reddit reuses the same gates: an approved link post may have an empty body, its approval hash covers the subreddit/type/title/body/link, live requirements are re-read before sending, and the submission id/URL are stored without the body or tokens. LinkedIn validates `LINKEDIN_API_VERSION` before anything is claimed, so a malformed or sunset version fails closed instead of creating a failed publication. Its author URN always comes from the verified connection, and because LinkedIn has no idempotency key an ambiguous send stays `sending` and is never retried automatically. Most LinkedIn apps receive no refresh token, so the expiry path only refreshes a connection that actually has one; otherwise the account is disconnected and the owner is asked to reconnect. Slack reuses the same approval/hash and duplicate gates but additionally requires a selected, verified `channelId`; the workspace and channel are resolved server-side from the connection, never from the request body. `chat.postMessage` is called once per draft, the Slack `ts` and channel id are stored as the external id/target, and an ambiguous result (no `ts`, timeout, or lost response) stays `sending`/`uncertain` and is never resent. A `missing_scope` or `not_in_channel` failure does not disconnect a working install; only `invalid_auth`/`token_revoked` marks it disconnected. WhatsApp does not go through this engine's network path: `prepareWhatsAppShare`, `markWhatsAppOpened`, and `markWhatsAppShared` revalidate the owner, approval, and hash at every step and use `storage.transitionPublication` for compare-and-set state changes, so the history distinguishes Prepared from Opened in WhatsApp from Manually marked shared and never says sent or delivered. A WhatsApp manual row stores `mode: 'manual'`, a content hash, and a timestamp, never the message text or a fabricated external id.
- `publicationState.ts`: dependency-free derivation shared by the API and the `/publishing` UI. Maps a draft plus its publication row to Needs approval, Ready, Publishing, Published, Failed, or Check the channel. A `sending` row older than 15 minutes becomes `uncertain` and is never retryable, and the same constant is used by `publish.ts`. Manual X and WhatsApp publications are labelled as marked by hand and explicitly unverified; WhatsApp also distinguishes Prepared and Opened in WhatsApp from Manually marked shared.
- `x/`: X-specific helpers, isolated from the generic adapters.
  - `x/text.ts`: official weighted counting through `twitter-text` (Latin 1, CJK/emoji 2, every URL 23), a 280 limit per post, and a 25-post thread cap. `threadText(parts)` is the canonical blank-line join stored in `draft.text`, so approval hashes and duplicate checks stay unchanged. Thread parts are validated again at send time.
  - `x/pricing.ts`: the single source of X prices. The verified official rates are $0.015 per create request and $0.200 per create request that contains a URL (verified 2026-11-11). No other module hardcodes a price. `estimateXThread` returns request count and micros; manual publishing is always $0.
  - `x/usage.ts`: the app-wide monthly budget (`X_MONTHLY_BUDGET_USD`, fails closed to 0). A reservation is written before the first request and settles to `committed` on success, uncertain or partial-thread outcomes, or `released` on a definitive failure. Reserved and committed rows count against the budget; released rows do not. An exhausted budget blocks automatic publishing only.
  - `x/pkce.ts`: S256 PKCE verifier/challenge.
  - `adapters/x.ts`: X OAuth 2.0 Authorization Code client (`tweet.read tweet.write users.read offline.access`), token exchange and refresh, account verification, revocation, and `POST /2/tweets` with `reply.in_reply_to_tweet_id` for threads. Timeouts are enforced; a missing response id or network error becomes `uncertain`, never an automatic resend. `MockXClient` is deterministic and is the default unless `PUBLISHING_TRANSPORT=live`.
  - `adapters/reddit.ts`: official Reddit OAuth client: authorization URL with `duration=permanent` and `identity read submit`, Basic-auth code exchange and refresh, `GET /api/v1/me`, subreddit search/about/rules/post-requirements, `POST /api/submit` for `self` or `link` posts, and token revocation. HTTP 200 bodies with `json.errors` become typed failures, `resubmit=false` prevents a second post, `x-ratelimit-reset` supplies the retry hint, and a missing id or transport failure becomes `uncertain`. A unique `REDDIT_USER_AGENT` is required. `MockRedditClient` is deterministic and is the default unless `PUBLISHING_TRANSPORT=live`.
  - `adapters/linkedin.ts`: official LinkedIn member client: authorization URL for `openid profile w_member_social`, token exchange and `GET /v2/userinfo` identity verification (`sub` → `urn:li:person:{sub}`), and `POST /rest/posts` with `LinkedIn-Version` and `X-Restli-Protocol-Version: 2.0.0`. A 201 must carry `x-restli-id`; without it, or on a network error, the send is `uncertain`. Posts are member-only (organization publishing needs separate products and approval and is not implemented). `MockLinkedInClient` is deterministic and is the default unless `PUBLISHING_TRANSPORT=live`.
  - `adapters/slack.ts`: official Slack OAuth v2 (`oauth.v2.access`) and Web API client. `chat.postMessage` sends the approved text; `conversations.list` returns public channels plus private channels the bot is a member of (paginated, archived excluded, de-duplicated); `conversations.info` and `auth.test` verify a destination, and `auth.revoke` disconnects. Every response is validated by its JSON `ok` flag, not only the HTTP status, so HTTP 200 with `ok: false` becomes a typed `SlackError` (`invalid_auth`, `token_revoked`, `missing_scope`, `not_in_channel`, `channel_not_found`, `is_archived`, `restricted_action`, `msg_too_long`, `ratelimited`). A 429 carries Slack's `Retry-After`, and a send without a `ts` or with a transport failure is `uncertain`, never resent automatically. `MockSlackClient` is deterministic and is the default unless `PUBLISHING_TRANSPORT=live`.
- `linkedin/`: LinkedIn-specific helpers, isolated from the generic adapters.
  - `linkedin/config.ts`: the single source for the Posts API version. `LINKEDIN_API_VERSION` (default `202610`) is parsed as `YYYYMM` and rejected if it is malformed or older than LinkedIn's 12-month support window; `linkedInApiHeaders(version)` returns the `linkedin-version` and `x-restli-protocol-version` headers every LinkedIn request carries. A malformed or sunset value fails closed with `LinkedInConfigError` before any send, and a missing client id/secret fails closed without touching drafting. `linkedInPostUrlFromUrn` builds a feed URL only from `urn:li:share:`/`urn:li:ugcPost:` ids, and `linkedInMemberUrn` turns the verified `sub` into `urn:li:person:{sub}`.
- `reddit/`: Reddit-specific helpers, isolated from the generic adapters.
  - `reddit/validate.ts`: static composer checks (title, body, subreddit name, self body, public http(s) link) and the canonical approval payload/hash covering subreddit, type, title, body, and URL. `redditLiveChecks` applies only rules the subreddit API reports (community type, banned/muted, submission type, title/body limits, required or blacklisted domains/strings, flair/gallery) and lists what cannot be verified, including the moderator disclaimer.
  - `reddit/discovery.ts`: per-user **and per-project** caches for search and details; cached permissions are never authoritative, and the publish path reads the live requirements again.
  - `reddit/markdown.ts`: small escape-first Markdown renderer for the Reddit preview. Links are limited to http/https and code spans are not re-parsed.
- `slack/`: Slack-specific helpers.
  - `slack/config.ts`: the bot scopes (`chat:write channels:read groups:read`, no user scopes), the documented 4,000-character message limit, the 15-second request timeout, the callback path, `isSlackConfigured()`, and `slackRedirectUri()` built from `APP_URL`. A missing client id or secret fails closed.
  - `slack/mrkdwn.ts`: escape-first Slack mrkdwn renderer for the preview. HTML is escaped before styling, links are limited to http(s), mentions/channel refs are limited to `[@#][A-Za-z0-9]+`, and unknown angle-bracket text stays literal, so the preview cannot inject HTML.
- `whatsapp/`: manual sharing helpers; there is no WhatsApp API, OAuth, credential, or Business account anywhere in this app.
  - `whatsapp/url.ts`: the official `https://wa.me/?text=…` click-to-chat link. `encodeURIComponent` preserves line breaks and URLs, and building the link never contacts WhatsApp.
  - `whatsapp/share.ts`: owner/approval/hash/composer gates and the race-safe manual lifecycle `prepared → opened → published`. Preparing records intent and returns the share link; opening WhatsApp is recorded separately; marking shared stores `mode: 'manual'` with no external ids and always returns `verified: false`. A draft edited after approval cannot be shared, a second share is refused, and no step makes a network call or claims delivery.

Milestone 5 adds Reddit. Owners connect their own account and publish text or link submissions through the official OAuth API. Static checks run on save/approve; the subreddit's live rules are read again immediately before publishing, and anything the API cannot report is shown as unverifiable rather than guessed. Commercial/high-volume access is not approved or priced here.

Milestone 6 adds LinkedIn member publishing. Owners connect their own account through LinkedIn OAuth (`openid profile w_member_social`, no PKCE because LinkedIn does not document it), Crewlink verifies the member through `/v2/userinfo`, and a text post is sent to the versioned `POST /rest/posts` endpoint with the member URN taken from the connection. Organization publishing needs separate LinkedIn products, `w_organization_social`, and page-admin approval; it is documented but not implemented. The API version lives in one module, so an upgrade changes one configured value.

Milestone 7 adds Slack automatic publishing and WhatsApp manual sharing. Slack uses the official OAuth v2 install with only the bot scopes `chat:write channels:read groups:read`; the owner installs the Crewlink app in their workspace, picks a public channel or one the bot has already joined, and publishes approved text with `chat.postMessage` (Slack mrkdwn, 4,000-character limit, link previews on). Crewlink verifies the channel server-side, stores the Slack `ts` as the external id, and treats an ambiguous send as `uncertain` without resending. WhatsApp has no official API for personal accounts, so nothing is automated: Crewlink validates an approved draft, builds an official `https://wa.me/?text=…` link, and records Prepared, Opened in WhatsApp, and Manually marked shared. It never claims a WhatsApp message was sent, delivered, or read. The `/publishing` UI covers Discord, Telegram, Slack, X, Reddit, LinkedIn, and WhatsApp; Bluesky and Mastodon remain API-only. AI drafting is not implemented, and no unofficial API, browser automation, or WhatsApp Web session is used anywhere. Live Discord/Telegram/Slack/Bluesky/Mastodon/X/Reddit/LinkedIn calls are untested against the real APIs, and the WhatsApp share link has not been verified end-to-end on a device; `PUBLISHING_TRANSPORT=mock` is the default and no real post or credit is created in tests.
