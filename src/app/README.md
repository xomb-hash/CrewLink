# App Router (Next.js)

Next.js App Router providing server-rendered pages and API Route Handlers.

## Pages
- `page.tsx` + `HomeClient.tsx`: Landing page for signed-out visitors. Signed-in owners see their connected projects as a card grid with `All / Public / Private / Referral / Direct / Screening` filters and topbar search (`/?q=`), plus a "Projects looking for collaborators" preview limited to public projects. Every card opens the project details modal over the current page.
- `discover/page.tsx` & `DiscoverClient.tsx`: Browse public projects from other creators with search. The server filters through `isDiscoverable`, so private referral projects never appear; cards open the project details page.
- `explore/page.tsx` & `ExploreClient.tsx`: Explore public projects with search and role filter pills, using the same project card design as Discover; the page and `/api/explore` both apply the same discoverability rule.
- `applications/page.tsx` & `ApplicationsClient.tsx`: Tracker for the signed-in user's join requests, including private referral requests, grouped by status with a link back to Explore. Approved requests show contributor status and, for public repositories, a fork link and pull-request guidance.
- `@modal/(.)join/[slug]/page.tsx` + `ModalClient.tsx`: Intercepting parallel route that renders `ProjectDetailsModal` over Home/Discover on client navigation. `@modal/default.tsx` renders nothing elsewhere. Closing calls `router.back()`; a refresh or shared `/join/[slug]` link renders the full join page instead.
- `dashboard/page.tsx` & `DashboardClient.tsx`: Owner dashboard with a GitHub profile block, project cards (reusable referral link with copy/share, usage count, optional limit and expiry, revoke and regenerate), applicant review (Approve/Reject), a "Projects you joined" section, and advisory banners.
- `publishing/page.tsx` & `PublishingClient.tsx`: Owner-only publishing page for Discord, Telegram, Slack, X (manual and automatic), Reddit, LinkedIn, and WhatsApp; Bluesky and Mastodon are available through the APIs. Connect, change, verify, or disconnect a destination; generate, edit, save, and approve drafts; publish with an explicit click. Draft cards show Needs approval, Ready, Publishing, Published, Failed, or Check the channel. Failed sends offer a manual retry; uncertain sends have no action and are never resent automatically. The Slack section adds workspace connection, bot-visible channel discovery, channel selection, an mrkdwn composer with preview and counter, and publish confirmation. The Reddit section adds subreddit search/details, live validation, and a text/link composer with Markdown preview. The LinkedIn section adds member-only composition with a live counter and LinkedIn-style preview. X automatic publishing shows a cost estimate and requires confirmation, while X manual publishing is free and explicitly unverified. The WhatsApp section is manual-only: composer, live counter, preview, validate, copy, open the official share link, and mark shared, with Prepared / Opened in WhatsApp / Manually marked shared history and no delivery claim. The page calls the owner-enforced drafts and connection APIs and adds no posting logic of its own.
- `projects/new/page.tsx` & `NewProjectClient.tsx`: Centered create card reusing `CreateProjectForm`. The single Create link in the top right opens this page. Creation starts with the Private visibility (referral) selected; Public offers direct join (open requests) or screening first (screening link required), and both list the project in Discover.
- `analytics/page.tsx` & `AnalyticsClient.tsx`: Owner-only analytics workspace with project and range filters (7/30/90/custom), Overview, Platforms, Posts, Top content, Audience, Posting time, Campaigns and AI insights tabs. Platform-reported metrics are shown separately from Crewlink-calculated engagement, unavailable metrics render as an em dash, and AI output is labelled unverified. It calls the owner-enforced `/api/analytics/*` routes and never publishes.
- `ai/page.tsx` & `AiWorkspaceClient.tsx`: Owner-only AI Studio with sections A–G (campaign builder, research workspace, editable strategy, content studio, review center, scheduling calendar, analytics), the project brand profile, provider status, and agent activity. It calls the AI APIs below, saves drafts through the existing draft store, and links to `/publishing` for approval and publishing. It never publishes.
- `join/[slug]/page.tsx` & `JoinClient.tsx`: Direct-visit join page (refresh or shared link) presenting the project overview, an "About the creator" card (avatar, GitHub link, account age, public repos, optional note), the screening task (if configured), and request submission. Referral projects accept the reusable code in the link path (`/join/CREW-XXXXX`); legacy `?ref=<code>` links still work. Direct-join projects take a plain request. A revoked, expired, limited, used, or unknown code shows the matching server message. Applicants can add GitHub/LinkedIn profile links and attach a PDF resume (max 5 MB), with owner-marked fields enforced as required.

## API Routes
- `auth/github/route.ts`: Initiates GitHub OAuth flow (with rate limiting).
- `auth/github/callback/route.ts`: Exchanges code, sets secure signed session cookie.
- `auth/logout/route.ts`: Clears session cookie and logs out.
- `api/auth/me/route.ts`: Current authenticated user profile.
- `api/repos/route.ts`: Repositories where user has admin access.
- `api/projects/route.ts`: GET owner projects; POST create new project (JSON or multipart with optional logo, rate limited).
- `api/projects/[id]/route.ts`: GET project details (owner-enforced); DELETE project (owner-only, removes applicants, drafts, logo, and resume files; the GitHub repository is untouched).
- `api/projects/[id]/logo/route.ts`: Public project logo image (404 when the project uses generated art).
- `api/projects/[id]/referral-code/route.ts`: Owner-only referral management for referral projects. POST generates a unique reusable `CREW-` code (optionally with settings), PATCH updates the usage limit and/or expiry, and DELETE revokes the link. Responses include the code, usage count, settings, and current share links.
- `api/projects/[id]/applicants/[applicantId]/approve/route.ts`: POST approve applicant as a Crewlink contributor (updates status and sends a notification; makes no GitHub call and grants no repository permissions).
- `api/projects/[id]/applicants/[applicantId]/reject/route.ts`: POST reject applicant (with notification).
- `api/join/[slug]/route.ts`: Public project join page data (never exposes the invite code).
- `api/join/[slug]/apply/route.ts`: Applicant join request accepting JSON or multipart (invite code, message, GitHub/LinkedIn links, optional PDF resume). Accepts the code either in the URL path or the body. Each use creates its own applicant record, duplicate applications are rejected, and revoked, expired, limited, used, or mismatched codes return 400 with an explanation. Enforces required credentials, rate limiting, and notification.
- `api/notifications/route.ts`: Signed-in activity feed (pending join requests on owned projects and decisions on the user's applications).
- `api/platforms/connections/route.ts`: Signed-in owner connection list (GET, optional `projectId`, owner-enforced) and connection upsert (POST, rate limited, secrets never echoed). Bot platforms take only `channelId`, are verified server-side before activation, and reject pasted tokens. Bluesky takes `identifier` + `appPassword` and returns an encrypted-session summary. Mastodon takes `instanceUrl` and returns an `authorizationUrl`. Rejects manual platforms, pasted account tokens, and projects the caller does not own.
- `api/platforms/connections/[id]/route.ts`: DELETE disconnects an owned connection and wipes its encrypted token material.
- `api/platforms/connections/[id]/verify/route.ts`: Signed-in POST that re-verifies an owned creator-owned account (Bluesky session, Mastodon, X, Reddit, or LinkedIn credentials). Refreshes when the provider issued a refresh token and disconnects a revoked account; never accepts a token from the browser.
- `api/platforms/mastodon/authorize/route.ts`: Signed-in POST that registers the instance OAuth app and returns only an authorization URL. The client secret and state hash stay server-side.
- `api/platforms/mastodon/callback/route.ts`: OAuth callback. Validates the single-use hashed state, exchanges the code server-side, verifies the account, and redirects to `/publishing?mastodon=connected|denied|error`. A denial or failure clears the pending handshake.
- `api/platforms/x/authorize/route.ts` & `x/callback/route.ts`: X OAuth 2.0 Authorization Code + PKCE. The verifier, redirect URI and session binding live only in the encrypted pending payload; the callback consumes the hashed state atomically and redirects to `/publishing?x=…`.
- `api/platforms/reddit/authorize/route.ts` & `reddit/callback/route.ts`: Reddit OAuth (`identity read submit`, `duration=permanent`) using the same hashed, session-bound, single-use state; the callback verifies `u/{name}` and redirects to `/publishing?reddit=…`.
- `api/platforms/reddit/subreddits/route.ts` & `subreddits/[name]/route.ts`: Owner-only subreddit search and details (community type, posting rules, limits, flair/gallery) cached per user and project. Cached permissions are guidance only; the publish path reads them again.
- `api/platforms/linkedin/authorize/route.ts` & `linkedin/callback/route.ts`: LinkedIn OAuth (`openid profile w_member_social`, no PKCE). The callback verifies `/v2/userinfo`, stores encrypted tokens and the member id, and redirects to `/publishing?linkedin=connected|denied|error`.
- `api/platforms/slack/authorize/route.ts` & `slack/callback/route.ts`: Slack OAuth v2 with the bot scopes `chat:write channels:read groups:read` only. The callback exchanges the code server-side, verifies the bot with `auth.test`, stores only the encrypted bot token plus workspace/bot metadata, and redirects to `/publishing?slack=connected|denied|error`. A denial or failure clears the pending handshake.
- `api/platforms/slack/channels/route.ts` & `slack/channel/route.ts`: Owner-only channel discovery using the bot token only (public channels plus private channels the bot already belongs to; archived excluded, no auto-join) and channel selection. Selection rejects a missing, archived, or non-postable channel and invalidates approved Slack drafts when the destination changes.
- `api/drafts/[id]/whatsapp/prepare/route.ts`, `whatsapp/opened/route.ts` & `whatsapp/shared/route.ts`: Owner-only manual WhatsApp lifecycle. `prepare` validates ownership, the current approval and hash, runs composer checks, builds the official `https://wa.me/` link, and records `prepared` with `mode: 'manual'` without contacting WhatsApp; `opened` and `shared` advance through conditional transitions and always return `verified: false`. Repeat shares, cross-user calls, and drafts edited after approval are refused.
- `api/projects/[id]/drafts/route.ts`: Owner-only GET listing drafts with checks, the stored publication (never the text or a token), and a derived `publicationState`. POST creates missing drafts for the requested platforms.
- `api/drafts/[id]/route.ts`: Owner-only PUT to edit a draft, including X `threadParts` and Reddit title/body/subreddit/type/link and LinkedIn text. An edit resets approval and re-runs static checks; over-limit values are rejected, not truncated.
- `api/drafts/[id]/approve/route.ts` & `skip/route.ts`: Owner-only approval bound to the current text and sha256, and draft skipping.
- `api/drafts/[id]/publish/route.ts`: Owner-only POST that publishes one approved draft to Discord, Telegram, Bluesky, Mastodon, X, Reddit, or LinkedIn (rate limited). Re-checks approval and the approval hash, refuses duplicates and in-progress sends, and returns 409 for `uncertain` (stale or unrecorded sends, never retried) and `auth_revoked`, 429 for `rate_limited` with a retry hint, and 502 when the platform rejects the message. X automatic publishing additionally requires `confirmCost` and respects the monthly budget; responses never echo the text or any token.
- `api/drafts/[id]/manual-published/route.ts`: Free X manual path; records `mode: 'manual'` without contacting X and returns `verified: false`.
- `api/drafts/[id]/x/estimate/route.ts` & `reddit/check/route.ts`: Per-platform pre-send checks: the X request count, cost estimate and remaining budget, and the live Reddit subreddit rules with anything Crewlink cannot verify.
- `api/resume/[applicantId]/route.ts`: Authenticated PDF download for the applicant or the project owner only.
- `api/ai/*`: Owner- and project-scoped AI Studio routes. `status` returns provider/model/configured flags and research availability without keys; `projects/[id]/campaigns` lists and creates campaigns; `projects/[id]/brand` reads and writes the project brand profile; `campaigns/[id]` returns the campaign, ideas, schedules and status; `run` executes the research → strategy → generation → quality pipeline (rate limited, no duplicate concurrent run); `strategy` applies owner edits; `ideas/[ideaId]/generate` regenerates one idea; `schedule` and `schedules/[scheduleId]` create heuristic suggestions and accept manual overrides; `drafts/[id]/quality` reviews an AI draft; `analytics` collects internal counts. All routes require the signed-in project owner who created the campaign, never return credentials, and never approve or publish.
- `api/analytics/overview`, `posts`, `top`, `audience`, `timing`, `campaigns`, `status`: Owner- and project-scoped reads. `campaignId` is checked against the project, `range` accepts 7/30/90 days or an explicit date range, and responses never include credentials.
- `api/analytics/sync/route.ts`: Owner-only manual sync (rate limited), bounded by post count and deadline. Records per-platform status, never retries indefinitely, and never blocks publishing. The database lease makes it safe across instances.
- `api/analytics/sync/scheduled/route.ts`: Service-token scheduler endpoint, disabled unless `ANALYTICS_SCHEDULER_TOKEN` is set (>=32 chars) and rate limited. It starts no worker and never returns credentials.
- `api/analytics/insights/route.ts` & `insights/[id]/accept/route.ts`: Owner- and campaign-scoped AI analyst. Requires the M8 provider (503 when unconfigured), short-circuits on insufficient data, stores validated advisory output, and records accept/dismiss; it never changes a campaign. AI numbers must be validated fact placeholders; the backend renders every value.
- `api/analytics/report/route.ts`: Owner-only CSV or PDF performance report with explicit limitations; rate limited.
- `api/health/route.ts`: Enterprise health check reporting service uptime, version, and database connectivity.
- `api/webhooks/github/route.ts`: GitHub webhook handler verifying HMAC-SHA256 signatures to record when an applicant is added to the repository manually by the owner.
